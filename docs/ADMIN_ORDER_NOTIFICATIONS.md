# GrocerAI admin order notifications

The order flow now keeps the existing admin Orders page and adds:

- Admin order list enriched with customer name/email and delivery address.
- Admin dashboard polling every 10 seconds while `/admin` is open.
- Browser sound alert for newly detected orders (click **Enable sound alerts** once per session; browsers require a user gesture).
- Optional email alert through Resend.
- Optional WhatsApp alert through Twilio WhatsApp.

## Configure email (Resend)

Add these values to `server/.env`:

```env
RESEND_API_KEY=re_...
ADMIN_NOTIFICATION_EMAIL=your-inbox@example.com
EMAIL_FROM=GrocerAI <onboarding@resend.dev>
```

For Resend's test sender, send only to the email address permitted by your Resend account. For real admin delivery, verify a domain in Resend and set `EMAIL_FROM` to an address on that verified domain.

## Configure WhatsApp (Twilio)

Add these values to `server/.env`:

```env
TWILIO_ACCOUNT_SID=AC...
TWILIO_AUTH_TOKEN=...
TWILIO_WHATSAPP_FROM=whatsapp:+14155238886
ADMIN_WHATSAPP_TO=whatsapp:+91XXXXXXXXXX
```

For the Twilio WhatsApp Sandbox, join the sandbox from the admin's WhatsApp number using the join code shown in Twilio Console. Replace the sample `TWILIO_WHATSAPP_FROM` with the WhatsApp sender assigned by Twilio if it differs. `ADMIN_WHATSAPP_TO` must use international format prefixed with `whatsapp:`.

## Start and verify

1. Keep all existing `server/.env` values; append the notification variables rather than replacing the file.
2. Restart the backend with `npm start`.
3. Sign in with an account whose database role is `admin` and open `/admin`.
4. Click **Enable sound alerts** once.
5. From a separate customer account/browser, place a test order.
6. The admin dashboard should show the order within about 10 seconds and play a sound. Email/WhatsApp delivery depends on the corresponding provider credentials and sender/recipient verification.

The order is saved before notifications are attempted. If Resend or Twilio is unavailable, the order still succeeds and the backend logs the notification error. Check the admin dashboard's notification status line and the server terminal for provider errors.

## Security notes

- Never commit `server/.env` or share API keys, Twilio auth tokens, or admin phone numbers publicly.
- Admin endpoints are protected by the existing database-backed `auth.admin` middleware.
- Browser alerts require the admin page to remain open. Email and WhatsApp notifications are sent server-side and do not require the admin page to be open.

## Separate admin and shopper sign-in

- Shopper sign-in and registration: `/login` (admin accounts are rejected by the shopper login endpoint).
- Private admin sign-in route: `/admin/login` (not linked from the shopper navigation).
- Admin dashboard: `/admin` (server-side admin role check applies to every admin API request).
- Admin login is handled by `POST /api/auth/admin/login`; shopper login uses `POST /api/auth/login`.
- Only a database user whose role is `admin` can sign in through the admin endpoint. Do not rely on the hidden URL as security; the server role check is the security boundary.

For production, replace the seeded demo admin account/password with a private administrator account and use a strong unique password. The demo seed credentials are for local development only.


## Razorpay online payments

GrocerAI supports Razorpay Standard Checkout for UPI/QR, cards, netbanking and wallets where enabled for the merchant account. The backend creates the Razorpay order, verifies the checkout signature, fetches the payment from Razorpay and only creates a paid order after the payment is captured. Raw card details are never sent to or stored by GrocerAI.

1. Create/activate a Razorpay merchant account and complete the provider's KYC/onboarding. Link the bank account where settlements should be received.
2. In Razorpay Dashboard, switch to **Test Mode** and create API keys.
3. Add `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` to `server/.env` (copy the names from `.env.example`). Never put the secret in frontend variables or commit it to GitHub.
4. Restart the backend. Checkout shows the online option when both keys are configured.
5. Test with Razorpay's official test payment methods. Switch to Live Mode and use live keys only after testing and account activation.

UPI QR is generated by Razorpay Checkout for the transaction; it is not the merchant's personal static UPI QR. The exact methods shown depend on the merchant account's enabled methods and the device/browser flow. Customer payments settle to the bank account registered with Razorpay, after gateway fees and according to the settlement schedule. A local `STORE_MODE=local` setup is for development only; use a persistent production database and HTTPS for live payments.
